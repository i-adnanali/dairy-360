# Angular remediation browser acceptance — 4–5 October 2026

Baseline: `0d0cc25` on main. Initial working tree contained only existing untracked `docs/reviews/`; those files are inventoried in [preserved-reviews.sha256](preserved-reviews.sha256). No commit, push, deployment, publication, dependency installation or upgrade was performed.

Used installed dependencies and Node 22.22.3. The documented registry harness remained in memory throughout: production frontend at localhost:6512 → task fault proxy at 127.0.0.1:6511 → memory harness at 127.0.0.1:6510. The proxy checks `memory === true` before starting and has a fixed upstream. Storage-target tests mock only the `/storage` response; the displayed `/synthetic/acceptance-a.db` and `acceptance-b.db` are fictitious names, never opened files. All writes and attachments are synthetic. No production endpoints, persistent database or model API were accessed. Fixtures were created on 4 October and retained in that process across the 5 October resume; later screenshots correctly use 5 October as today.

Browser: Codex in-app Chromium, production Angular bundle. Desktop viewport 1440×1000; mobile viewport 390×844 (desktop emulation, not a native phone). DOM snapshots, actual keyboard actions, focus checks and screenshots are distinguished below from component tests. Initial and final production builds use `CI=true NG_BUILD_MAX_WORKERS=1 npm run build:angular`.

## Evidence and reproduction

[Fault proxy](fault-proxy.mjs) is task-only tooling, not application code. Start the documented memory harness on 6510, then this proxy on 6511, then `npm run harness:serve -- --port=6512 --api=http://127.0.0.1:6511`. Its [fault configuration](faults.json) is read on each request. Rules match path and optional method; `delay` holds a response, `status/body` returns synthetic responses, and `drop` forwards a write then closes the response. The [request log](requests.jsonl) records synthetic payloads, keys, timestamps and the exact rule active for every browser/API scenario. [Concurrent crop script](concurrent-crop.mjs) includes this run's disposable crop ID; rediscover IDs for a fresh harness rather than reusing them blindly.

The initial full-page PNG captures from the in-app browser rendered only part of the app's nested scrolling region and should not be treated as complete layout evidence. Final viewport PNGs (assistant-mobile, calf-fixed-mobile, health-fixed-focus and report-desktop) were visually inspected. DOM snapshots are primary evidence for full form content.

Remaining material limits: native print pagination/clipping, actual screen-reader announcements, native mobile keyboards, exhaustive fault injection and real operator acceptance. Production and live assistant execution were intentionally excluded. Known native LMDB local-cache failure is unchanged; its documented workaround continues to build the final code.

Final console inspection found only the earlier lazy-chunk load failure caused by rebuilding static assets under an already-open old bundle; reloading the production page resolved it. No further application console errors were observed in the final replay. Temporary theme/viewport overrides and proxy faults were reset.

Cleanup: stopped all three task-owned local processes (memory harness, fault proxy and static frontend). Synthetic database state was discarded; the evidence and reproduction tooling remain.
