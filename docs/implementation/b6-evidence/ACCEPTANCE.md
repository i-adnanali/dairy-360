## Write-safety evidence boundaries

- `write-safety.spec.ts` simulates a write accepted before its response is lost, verifies exact original path/body/key on retry, suppression of concurrent requests and edit unlocking only after definite refusal. It never contacts farm data.
- `feed.spec.ts` checks original/proposed provenance, unchanged/reverted correction prevention and explicit conflict discard; `health.spec.ts` checks latest revision separation, lost attachment response bytes/key, retained visit purpose, void cancellation and started-round validation.
- Draft/session/routing tests cover stale read generations, raw input, dirty-only unload registration and pagination retention. Listener registration is not evidence of native browser unload UI.
- Server vaccination rounds are atomic under their existing transaction. A failed row does not imply partially committed clinical rows. Attachment upload and record linkage are separate operations; tests retain failed upload snapshots. No new batch outcome semantics were invented.
- Chat-store tests check duplicate/unknown decisions, all-card aggregation, failed approval with unknown outcome and no replay. B6 synthetic Approve/Reject exercises UI traffic only; no executor exists in the fixture.
