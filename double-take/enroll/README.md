# The synthetic enrolment subject (Cycle 7 FU-3)

Put **one** image here, named `synthetic_1.jpg` (or `.png`), before running
`npm run enroll:synthetic -w server`.

Files other than this README and `PROVENANCE.txt` are gitignored. The image is not committed:
this repo is public, and a face image in git is a face image in git even when
the face is machine-generated.

## Why there is exactly one, and why it must be synthetic

FU-3 validates Double Take's payload shape against a **street-facing** camera,
so it processes the faces of members of the public who have not consented to
biometric processing. Two facts from the validation pass shape this directory:

- With an **empty** gallery, both supported detectors return a hardcoded
  `confidence: 0` and `name: 'unknown'` for every face, and `matches` / `misses`
  are always empty. The 0–100 confidence scale — the exact claim Cycle 4 got
  wrong by 100× — is then unmeasurable, which defeats the point of the slice.
- Enrolling a **real** person to fix that would mean fingerprinting someone in
  order to study strangers. Enrolling a **synthetic** face gives every passer-by
  a genuine similarity score to diff against, while the only identity in the
  gallery belongs to nobody.

So: exactly one subject, and it must not be a photograph of a real person. That
explicitly rules out Double Take's own bundled `lenna.jpg` — Lenna is a real
person, and using her would substitute one non-consenting individual for
another. It equally rules out stock-photo and "random user" APIs, which serve
photographs of real people.

## Provenance is the whole basis for this being acceptable

Record where the image came from, in `PROVENANCE.txt` next to it. "It is
synthetic" is the entire reason enrolling it is defensible, so that claim needs
to be checkable by whoever reads this next — not taken on trust.

Prefer an image carrying **C2PA content credentials**, which make the claim
verifiable rather than asserted. The IPTC `digitalSourceType` to look for is:

```text
http://cv.iptc.org/newscodes/digitalsourcetype/trainedAlgorithmicMedia
```

That code means the media was generated by a trained algorithm — i.e. not a
photograph of a person. You can read the credentials out of a file with:

```bash
strings -a <file> | grep -aiE "softwareAgent|claim_generator|digitalSourceType"
```

## What the harness does with it

`npm run enroll:synthetic -w server` will:

1. refuse to run if the gallery already holds anything other than
   `synthetic_1`, so a real enrolment cannot be inherited from a previous run;
2. register this image as the single subject `synthetic_1`;
3. **restart DeepStack** — its `/face/recognize` only sees subjects that were
   present at process start, so without the restart every face comes back
   `unknown` at `confidence: 0` and the run silently degenerates into the
   empty-gallery case above;
4. verify recognition actually resolves `synthetic_1` on this image, because a
   gallery-contents check alone passes while recognition is still broken.

`npm run capture:doubletake -w server` re-runs check 1 and 4 as preconditions
and refuses to capture if either fails.
